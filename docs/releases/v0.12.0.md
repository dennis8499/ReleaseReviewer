# Release Reviewer 0.12.0

本版改善啟動診斷、同次審查的發布重試，以及摘要與引用的正確性，並補上批次閱讀和可驗證的品質驗收工具。

## 行為改善

- `capabilities.runtime_paths` 同時揭露 session 與共用 Git network runtime 的位置及設定來源。預檢指出失敗位置與 fetch 是否開始；操作範例補齊共用 runtime 設定。
- 正式報告寫入完成前的權限或檔案占用錯誤回傳 exit 3，保留同一 request 與固定快照。修正位置後可離線重跑 `finish`，成功時只產生一份正式報告；完整性錯誤仍終止。
- `check` 提供遮蔽後的摘要預覽與已知引用行號上限診斷。完整審查不能發布預設摘要；真實未完成結果仍可如實發布。交付前以 `status --summary` 核對固定正文收據，保留人工 Checklist 的可編輯性。
- 能力旗標控制的 `view --requests-file` 提供唯讀批次閱讀，整份回應上限為 24 KiB；批次游標與各頁續讀游標獨立保留。
- 新 context 的 `entry-base/v1` 規則要求每個 P0／P1 說明本次變更如何新增觸發條件，並附入口 base 證據或已擷取的新路徑證據。helpers 驗證結構，reviewer 負責語意核對。

## 驗證與已知限制

本機 Windows／Python 3.14.7 的完整回歸 318 項，加上後續新增的 4 個測試方法，共 322 個不同方法通過；發行契約測試另有 25 項通過。正式發布流程要求 Windows／Python 3.10 與 3.14 的完整矩陣通過，並從相同 commit 的可信 CI 證據提升 canonical ZIP 與 SHA-256 附件。

新增匿名回歸案例涵蓋既有問題、新呼叫觸發舊程式、刪除仍有 consumer 的端點，並保留缺失 consumer 的必要缺口。品質 runner 使用專用 Codex profile、審查前後的 enabled-skill inventory 與固定 payload hash；獨立評分匯入器核對矩陣及報告 hash、誤報、漏報、假完成、必要缺口、證據與部署依賴。

本機 Codex CLI 0.166.0 的無技能與指定技能 inventory probes 均通過，模型審查呼叫數為 0。實際三模型矩陣與獨立語意評分尚未完成，因此不宣稱模型品質、Agent 工具呼叫數或端到端速度改善。支援 Repo 快照快取仍停用。操作及評分格式見[可靠性與品質驗收](../review-reliability.md)。

## 相容性

維持三個使用者輸入、Context／Draft／Report v3、固定 SHA、完整覆蓋、獨立發布驗證、人工 Checklist 與共用 Git 鎖契約。明確選取的每個 remote 在同一 request 最多 fetch 一次，擷取後沿同一快照離線操作。歷史 v3 context 未帶 `entry-base/v1` 時沿用原有規則；舊 CLI 與單頁 `view` 繼續支援。

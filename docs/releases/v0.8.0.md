# ReleaseReviewer 0.8.0

發布日期：2026-10-23。由正式版 0.7.0 升級。

## 本版更新

- 新增獨立、可恢復的 start／step／check／finish／status／cancel 請求，保留成功操作、可修復輸入錯誤與發布收據。
- 分開執行 manifest 結構診斷與完整驗證；草稿及 artifact 檢視不呼叫 Git，每輪驗證實際使用的 Repo，finish 完整驗證所有固定來源。
- 在同一固定 context 重用經摘要檢查的搜尋結果，保留七類依賴、入口 base 首次使用檢查、服務身分、功能鏈及既有 v3 契約。
- 使用串流與短 pack/index 檔名修復已重現的 Windows 深路徑問題，同時保留 checksum、雙檔 SHA-256 及歷史 manifest 相容性；owned Git 根超過 220 UTF-8 bytes 時明確拒絕。
- 發布完成後可重試清理，已發布的 status／check 保留權威審查結果、原有缺口及人工部署確認。

## 已接受的驗收限制

本次依使用者於 2026-10-23 明確接受限制的決定發布正式版。原候選版的正式模型品質／效能驗收仍為未通過，沒有將原紀錄改為成功。完整自動化 CI 仍是獨立且必要的發布條件。

- 原目標要求大型案例 6/6 有效配對，端到端 candidate/base 耗時比中位數不超過 0.70；ReleaseReviewer 最終僅 4/6 有效，中位數為 1.1547，未達 30% 改善目標。
- 兩個 Reviewer 合計 48 次最終 agent 執行取得 47 份報告；另一次無報告失敗仍保留，不能宣稱 48 次完整審查均成功。
- 既有情境的嚴格品質失敗、額外風險判定與 runtime 所有權限制均保留原紀錄。本版未新增跨請求 fetch／pack 快取，也不宣稱模型或完整流程已加速。
- 既有 VS Code CLI 隔離安裝、installed-resources 流程及原固定深度回歸已執行；Native UI 與 production activation 未驗證，未宣稱任意深根皆可用。

本版維持技能公開介面相容。發布證據另外保存原始 acceptance-record、驗收摘要、必要報告與追蹤紀錄，以及本次正式 CI、來源提交及附件 SHA-256。

# Release Reviewer 0.11.0

This release implements the staged session improvements on the 0.10.1 payload while keeping Context, Draft and Report v3, the selected model, the full review scope, fixed SHAs, independent publication verification and one report per request.

## Changes

- Summary continuations now begin at the first omitted item. Lists, object fields and long strings carry explicit cursors, and page sizes are bounded by the serialized UTF-8 JSON response size. Patch output keeps the original bytes and SHA-256, supports BOM or explicit codec decoding, and marks reversible byte escapes when decoding is unavailable.
- Capture and review metrics now separate existing capture time, capture phases, Git command time and bytes, fetch time, network-lock wait, pack/index work, snapshot validation, manifest-lock wait, evidence reads, search, publication verification, cleanup, and CLI output bytes. Metrics unavailable from the host remain `null`.
- Session operations add `read-window`, structured field-addressed repair diagnostics, standalone hash-checked `view`, and bounded `status --summary`. Both standalone read-only queries avoid Git and artifact/manifest writes.
- `ReleaseReviewUpdates/v1` applies small draft edits with request ownership, expected revisions and idempotent update IDs. Durable progress records read evidence, cursors, excluded questions and next actions without treating saved evidence as a semantic review decision.
- Consecutive compatible case-sensitive literal searches share one Git grep command while retaining independent result payloads and saved IDs. Case-insensitive searches and publication's fresh verification replay retain their existing behavior.
- Session guidance now places UTF-8 batch, pagination, update/retry and recovery examples beside the corresponding CLI steps.

## Compatibility and limits

The old strict `read`, legacy session CLI, worklist IDs, same-request offline continuation, Context/Draft/Report v3, editable report checklist, and idempotent `finish` behavior remain supported. Each request still fetches each explicit remote at most once; local-branch requests and all post-capture operations remain offline.

The default-off supporting Repo snapshot cache is not included in this payload. It remains gated on isolation/corruption tests and a paired benchmark showing at least 20% warm-capture median improvement with no more than 5% cold-start regression. The supplied helper counters do not establish Agent tool-call reduction, end-to-end time improvement, or semantic review quality. Full Python 3.10/3.14 validation and the fixed-payload three-model/oracle matrix must pass before claiming those acceptance targets.

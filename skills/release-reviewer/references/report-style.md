# 上版檢查報告風格

報告是入口 Repo/review-reports 內的一份繁體中文 Markdown。標題為 `# 上版檢查: {Repo}`，二級章節固定依序為：

1. `審查結論`：先說本次判斷、已確認阻擋、待核對前置條件及真正缺口。
2. `問題總攬`：用表格連到問題詳情，簡述影響與處理方式。
3. `問題詳情（工程師參考）`：逐項提供問題名稱、影響說明、操作情境、建議處理；技術證據包含觸發條件、證據說明、影響範圍、工程修正建議及固定程式證據。用日常情境和精確技術原因分別服務讀者與工程師，避免重複貼上同一段文字。
4. `範圍與限制`：交代已提交差異範圍、缺口、未查環境；新增部署依賴與可編輯 Checklist 置於本節。依賴提醒與已確認程式阻擋分開呈現。
5. `技術審查紀錄（工程師參考）`：保留擷取起訖時間、固定 SHA、來源、Diff 起點、搜尋 ID／命中數、關聯判斷、功能鏈、覆蓋及執行紀錄；詳細紀錄可用 `<details>` 收合。

沒有問題時明說已檢查範圍未發現有證據的直接阻擋，仍交代限制及待確認部署條件。舊草稿欠缺新增說明欄位時標「未提供」，保留已驗證結論。

進度與最終回答採結果先行，簡單答覆一至三句；最後給唯一報告連結與重要阻擋／缺口。已安裝 `output-style/SKILL.md` 時可依其模式調整行文密度，固定章節、Checklist、證據及產生時判斷仍依本契約。

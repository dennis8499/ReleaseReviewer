# Release Reviewer 0.11.1

This patch release makes the consecutive case-sensitive literal search optimization active in the batch evidence path. Compatible searches for the same Repo, source, fixed ref and flags now use one Git grep subprocess. Each query still receives its own result, stable search ID and publication-time verification; case-insensitive searches and requests with incompatible identities retain the existing serial path.

## Validation

The release candidate is compared against the frozen 0.10.1 payload using six alternating baseline/candidate pairs for synthetic helper sessions and six pairs for dense search. The benchmark records semantic equivalence, total helper time, stage time, Git subprocess counts and the Git grep subprocess count and duration. See the paired results in `docs/releases/v0.11.1-session-benchmark.json` and `docs/releases/v0.11.1-search-benchmark.json`.

On Windows 11 with Python 3.14.7, all 36 session samples and all 12 dense-search samples succeeded with equivalent evidence. Session candidate/baseline median ratios were 0.993 for a single Repo, 0.980 for Group and 1.024 for no-change, within the 1.05 helper regression limit. In dense search, the evidence stage's median Git grep count fell from 5 to 3 and Git grep time from 0.171 s to 0.104 s; total evidence-stage median time was 0.654 s versus 0.645 s. Full dense-search helper time improved by about 1%.

These are helper-only measurements. They do not measure Agent tool round trips, model tokens, full Agent end-to-end time or semantic review quality. The optional supporting Repo snapshot cache remains disabled and is not part of this release.

## Compatibility

Context, Draft and Report v3, the selected model, full review scope, fixed SHAs, independent publication verification, legacy CLI, editable report checklist and idempotent `finish` behavior remain unchanged. Each request still fetches each explicitly selected remote at most once; all post-capture operations remain offline.

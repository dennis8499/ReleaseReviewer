# ReleaseReviewer 0.10.0 candidate acceptance

This candidate implements the runtime, evidence, paging, skill-layering, network, long-path ledger/cleanup, and release-checklist changes. The final skill payload passes the helper timing targets for single-Repo and Group sessions, preserves helper evidence equivalence, and passes the local Python 3.14 unit and release-contract suites. The full-Agent timing, three-model semantic matrix, and Python 3.10 CI gates remain open, so the overall improvement goal is not yet accepted.

The machine-level helper benchmark measures the complete session CLI flow, including capture, reads/searches, draft validation, publication and cleanup. Its time is not a substitute for end-to-end Agent time. Git subprocess counts are not HTTP or SSH request counts; unavailable transport/token metrics remain `null`.

The final helper benchmark used Windows 11 build 26300 and Python 3.14.7. The baseline is committed 0.9.0 at `82f9c71fc1c857cdeec7db8c37ff27239feac060` (payload SHA-256 `0ffe214ea727f54a8d2d03e4f63bbc2c0a89b7f7372e086c46e06afef38a68a4`); the measured candidate payload SHA-256 is `5ffca53b34c2d6e9dc71cee2ee9f0c6dd45cefa342be2ddb8bc3cb8beb7bfd00`. Across 30 samples, all helper calls succeeded with equivalent evidence, complete reports, successful cleanup, and zero local fetches. The candidate/base median ratios are 0.661 for single-Repo, 0.698 for Group, and 0.964 for no-change. The sandbox diagnostic showed that the baseline cannot create hard-link evidence views under that policy, while the candidate fallback completes; the paired timing was therefore run with the required local filesystem permissions.

## Release decision

Do not label this candidate as meeting the improvement goal while any target is missing or failed. A helper target requires all five pairs to succeed, a matching evidence digest, a complete published report, no blockers or static gaps in the synthetic helper fixture, and successful cleanup. A full Agent target requires the six paired Agent samples. A semantic target requires oracle-backed criterion-level review of all required runs; report creation or process exit alone is not a quality pass.

The repository CI workflow currently covers Windows/Python 3.10 and 3.14. This local environment has Python 3.14 only, so the Python 3.10 result must come from CI. The full-Agent six-pair targets and the three-model, oracle-scored quality matrix remain unrun; do not mark the overall improvement goal as achieved. The standalone candidate ZIP is a review artifact, not a formal release asset.
